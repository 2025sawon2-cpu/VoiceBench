# VoiceBench가 아직 AI처럼 들리는 이유

2026-09-24. 현재 코드, 선택된 참조 B, A/B/C 비교 음성, 기존 요청 #71~#75의
125개 원본 구간 WAV와 실행 기록을 분석했다. 사용자는 A/B/C 중 C를 선호했으나
여전히 시스템 출력의 AI 느낌이 크다고 평가했다. 이 문서는 원인 분석이며 생성 설정을 바꾸지 않는다.

분석자가 실제 음성을 청취해 금속성이나 감정을 판정한 결과가 아니다. 사용자 청취 의견,
코드에서 확인한 구조, 파형·인식 측정을 구분했다. 추정 피치, RMS, ASR 오류율은 자연스러움 점수가 아니다.

**핵심 판단**

우선순위가 가장 높은 원인은 발화 의도를 표현으로 연결하는 기능의 부족, 좁은 참조 조건,
구간 사이 말투 초기화, 자연스러움을 평가하지 않는 후보 선택 구조다. 현재 자료만으로
GPU 성능 부족, 클리핑, 과도한 가장자리 삭제를 주원인이라고 볼 근거는 약하다.
신경망 음성 코덱의 질감은 별도로 확인해야 할 후보이며, 원인 분리를 위한 실제 비교 파일을 만들었다.

**1. 목소리 복제와 상황에 맞게 말하는 능력 사이의 간극**

현재 Base 모델에는 낭독할 텍스트, 언어, 참조 음성·참조 대본, 샘플링 설정을 전달한다.
`x_vector_only_mode=False`여서 화자 임베딩뿐 아니라 원본 음성 코드도 사용하는 정상적인
문맥 기반 복제다. 화자 정보만 추출하고 운율 정보를 버리는 설정은 아니다.

다만 현재 API 경로는 “이 말은 체념인가 위로인가”, “앞 문장에서는 망설이다가 마지막에
확신하는가”, “어느 단어를 대비해 강조할 것인가”를 별도 입력으로 전달하지 않는다.
모델이 텍스트와 참조에서 추론하는 표현에 의존한다. `괜찮아요.`처럼 같은 글도 상황에 따라
다르게 말해야 하므로, 발음이 정확하고 화자가 비슷해도 사람의 의도와 어긋난 낭독이 가능하다.

`service.py`의 질문·전환·결론 분류는 문장 분할과 쉼, 문맥 연결 초기화에 사용된다.
이 메타데이터가 성대 긴장, 강조 단어, 감정 진행으로 변환되는 단계는 없다.
이는 구현에서 확인한 가장 큰 기능적 빈틈이며, 실제 청감에 미치는 크기는 청취 비교가 필요하다.

Qwen 공개 API도 Base의 음성 복제와 CustomVoice/VoiceDesign의 자연어 스타일 지시를
구분한다. 후자의 기능을 현재 소유자 목소리 복제에 그대로 적용할 수 있다고 가정하면 안 된다.
감정 필드만 추가하고 모델이 소비하지 않으면 실질적인 제어가 생기지 않는다.
[공식 모델/API 안내](https://huggingface.co/Qwen/Qwen3-TTS-12Hz-1.7B-Base)

**2. 현재 ‘표현형’ 설정은 말할 의도를 가르치지 않는다**

표현형과 안정형의 차이는 주로 샘플링 확률이다. 높은 temperature는 예측의 다양성을
늘리지만 적절한 감정이나 강조를 자동으로 보장하지 않는다. 의미와 맞지 않는 높낮이·말끝·
음색 변동도 생길 수 있다. 반대로 낮추면 안정적이지만 더 단조로워질 수 있어 단순 증감으로
해결할 수 없다. 특히 말의 큰 흐름을 만드는 talker와 세부 음향 코드를 만드는 subtalker를
동시에 변경하면 개선·악화 원인을 분리하기 어렵다.

현재 값이 잘못됐다는 실험 결과는 없다. 같은 대본·참조·Seed·C 조건을 고정하고 두 설정을
한 번에 하나씩 바꿔 비교해야 한다. Seed 13 자체가 AI 느낌의 원인이라고 볼 근거도 없다.
고정 Seed는 반복 가능성을 제공하며, 대본이 다르면 같은 음성을 반복하는 것은 아니다.

**3. 단일 참조의 역할과 한계**

선택된 참조는 9.95초의 한 발화다. 대본에는 밝게 웃기, 진지한 설명, 조용한 말하기가
언급되지만 그 단어가 들어 있다는 것만으로 세 가지 실제 발화 스타일의 예시가 제공되지는 않는다.
참조는 현재 그대로 유지해야 한다. 현재 녹음이 딱딱하다고 청취 판정한 것도 아니다.

사람 같은 결과를 위해서는 화자 동일성과 말투 적합성을 따로 평가해야 한다. 같은 화자의
차분한 대화, 설명, 회상 등 실제 녹음을 비교 참조로 준비하면 스타일 조건이 병목인지
검사할 수 있다. 긴 파일 하나를 넣는 것보다 목표 말투에 맞는 깨끗하고 일관된 예시가
유리할 수 있으며, 길이만 늘렸을 때의 개선은 보장되지 않는다.

우리 참조 전처리 기록에는 잡음 제거나 다이내믹 압축이 없다. 48kHz 원본을 24kHz로
리샘플링하고 선택 구간에 약 +10.53dB의 고정 게인을 적용해 피크를 -6dBFS로 맞췄다.
고정 게인은 상대적인 강약을 평탄화하는 압축과 다르다. 녹음 장치 단계의 처리·잔향·잡음은
이 기록만으로 확인할 수 없지만, 우리 전처리의 과한 노이즈 제거를 원인으로 단정할 근거는 없다.

원본을 Whisper Base로 검사한 문자 오류율은 1.89%이며 `본래`를 `볼래`로 인식했다.
이것만으로 녹음이나 참조 대본이 틀렸다고 볼 수 없다. 큰 누락·대본 불일치 경고는 없었다.

**4. C는 부분적인 문맥 연결이며, 장문 전체의 지속 상태는 아니다**

A는 모든 구간을 원본 참조에서 새로 시작한다. C는 원본 코드와 검증된 직전 합성 구간의
코드를 함께 참조하지만, 매 구간 새 생성 호출이며 앞 호출의 모델 내부 상태를 계속
유지하는 방식은 아니다. 합성 음성을 다시 참조로 인코딩하는 실험적 방식이므로,
앞 결과의 어색한 말투까지 이어받을 가능성도 있다. 코드 연결은 두 녹음의 음향적으로
연속된 한 장면을 의미하지 않는다.

현재는 화자·음색의 누적 변형을 제한하려고 한 번 연결한 뒤 초기화한다. 문단 전환,
전환·결론 시작, 앞 구간의 길이가 3~20초 밖인 경우, 검사 실패에도 원본 참조로 돌아간다.
따라서 긴 글에서 연결 효과가 계속 유지되지는 않는다. 연속성을 개선하려면 이 초기화와
누적 변형 사이의 균형을 실제 장문에서 검증해야 한다.

| 같은 예문 | A 기존 | B 한 번에 생성 | C 원본을 유지한 문맥 연결 |
| --- | --- | --- | --- |
| 생성 구간 | 15.68초 + 9.60초 | 24.16초 | 15.68초 + 8.88초 |
| 문자 오류율 | 0% / 0% | 0% | 0% / 1.75% |
| 연결부 피치 차이 절댓값 | 0.83반음 | 연결부 없음 | 0.17반음 |
| 연결부 RMS 차이 절댓값 | 0.73dB | 연결부 없음 | 0.98dB |

사용자는 C를 선호했다. ASR 0%, 연결부 0개, 더 작은 RMS 차이 중 어느 하나만으로
선호 결과를 설명할 수 없다는 중요한 단서다. 다만 하나의 Seed와 짧은 예문에서 얻은 평가다.
C의 첫 15.68초는 A에서 그대로 재사용했으므로 이 부분의 부자연스러움은 C에서도 동일하다.
생산 기본/MCP/API에는 C가 자동 적용되지 않는다. Studio에서 해당 비교 프리셋을 선택해야 한다.

**5. 지금 품질 관리의 목표는 ‘잘 읽었는가’에 가깝다**

현재 검사 항목은 발화 누락·반복, 인식 오류, 극단적인 길이, 거의 무음인 파일, 빈 파형,
클리핑 등이다. 음색의 진짜 같음, 문장의 적절한 강조, 감정 진행, 한국어 말끝의 자연스러움,
숨과 머뭇거림의 적합성은 점수에 포함되지 않는다. 실제 #71~#75의 125구간은 모두
Seed 13의 첫 후보가 통과해 다른 후보를 만들지 않았다.

자동 검사가 자연스러움을 나쁘게 만든다는 의미는 아니다. 부자연스러워도 발화가 정확하면
그대로 통과시키며, 더 좋은 후보를 고를 기회도 없다는 뜻이다. 경계 피치/RMS나 낮은 CER을
새 자연스러움 점수로 대체해도 같은 문제가 생긴다. 질문이나 강조는 큰 피치 변화가 오히려 필요하다.
`silence_ratio` 역시 낮은 진폭의 개별 표본 비율이므로 “전체 시간의 절반이 무음”처럼 해석하면 안 된다.

개선용 평가에서는 정확도와 화자 동일성을 유지하면서, 사람 같은 발화, 의미에 맞는 강조,
구간 연결, 음향적 합성 느낌을 따로 평가해야 한다. 후보를 더 만들 경우에도 자동 ASR 통과
후 청취 선호를 비교해야 하며, 자연스러움의 자동 평가기를 도입하면 한국어 사용자 평가와의
일치부터 확인해야 한다.

**6. 쉼·호흡·한국어 말끝을 다루는 정밀도가 낮다**

현재 구간 연결은 구두점/역할에 따른 몇 가지 목표 쉼과 디지털 무음을 사용한다.
#71~#75의 120개 연결 중 87개는 280ms로 계획돼 있다. 구간 내부 쉼은 모델이 만들므로
모든 문장이 같은 간격이라는 뜻은 아니다. 다만 긴 내레이션의 경계에서 정형화된 리듬이
반복될 가능성이 있으며, 말끝을 내리는지 유지하는지에 따라 필요한 쉼은 달라질 수 있다.

고정 진폭 문턱으로 가장자리를 자르는 방법도 숨과 약한 자음을 직접 구분하지 않는다.
이번 자료에서는 가장자리 삭제량의 중앙값이 앞·뒤 모두 0ms였고, 95백분위는 앞 318ms,
뒤 20ms, 최댓값은 앞 550ms·뒤 40ms였다. 가장 많이 삭제된 경우에도 에너지는 약
0.001153%로 작았다. 과도한 삭제를 주원인으로 볼 근거는 약하지만, 미세한 숨 보존 여부는
원본 구간과 최종 연결 음성을 청취 비교해야 한다. 문턱을 낮추거나 숨소리를 일괄 추가한다고
자연스러워지는 것은 아니다.

한국어는 같은 종결어미도 의미와 관계에 따라 다르게 끝맺는다. 현재 시스템은 낭독할
글을 거의 그대로 전달하며, 강조·발음 사전이나 의미에 따른 발화 단위 모델이 없다.
AI가 작성한 대본의 반복적인 어미·균일한 문장 길이·추상적 표현도 별도 원인 후보다.
이것은 사용자의 모든 대본이 문제라는 판정이 아니다. 원문을 보존한 상태의 TTS 평가와,
사용자가 허용한 구어체 대본 비교를 분리해야 한다.

**7. 코덱·음향 질감은 아직 확정할 수 없는 별도 원인**

Qwen은 텍스트에서 음성 코드를 생성하고 신경망 코덱으로 파형을 복원한다. 코덱의 압축과
복원 과정은 음향 세부에 영향을 줄 수 있다. 모델명의 12Hz는 음성 토큰의 시간 해상도이며,
출력 WAV의 샘플레이트가 12Hz라는 의미가 아니다. 현재 WAV는 24kHz PCM 16비트다.
금속성, 치찰음 번짐, 숨결의 질감 문제는 생성 운율과 분리해 검사해야 한다.
[Qwen 기술 보고서의 토크나이저 설명](https://arxiv.org/html/2601.15621v1#S2.SS2)

이를 위해 선택된 실제 참조를 현재 캐시의 코덱으로 인코딩·디코딩했다. 대본에서 새로운
음성을 생성하지 않았으며, GPU나 생산 설정은 건드리지 않았다.

- 원본 9.95초 → 복원 10.00초, 코드 크기 125×16, 24kHz 출력.
- CPU FP32 코덱으로 실행했으므로 GPU FP16 생산 경로와 완전히 같은 수치 조건은 아니다.
- Whisper 문자 오류율은 원본 1.89%, 복원 5.66%. 짧은 한 녹음의 인식 차이이므로
  금속성이나 인간적인 느낌의 악화를 입증하지 않는다. 음량 정규화도 하지 않았다.
- 비교 청취: `data/reports/naturalness-audit-20260924/codec-listen.html`.

복원 파일에서만 같은 합성 느낌이 생기면 코덱 기여가 의심된다. 둘 다 자연스러운데
대본 합성 결과만 어색하다면 생성된 운율·발음·참조 조건에 더 무게를 둬야 한다.
코덱 복원이 양호해도 모델이 잘못 예측한 음성 코드의 품질까지 보장하는 것은 아니다.

**8. 지금 근거로 우선순위를 낮춰야 할 설명**

- **GPU가 느려서 발음이 기계적이다:** 현재도 1.7B FP16을 쓰므로 성능 부족 때문에
  작은/과도하게 양자화한 모델로 바꿔 실행하는 상황이 아니다. 5070 Ti는 생성·비교 여유를
  늘리지만 말할 의도를 자동으로 보완하지 않는다. GPU·수치 방식이 달라 결과가 달라질 수는
  있으나 그 차이가 체계적으로 더 자연스럽다는 증거는 아직 없다.
- **높낮이가 없으니 크게 흔들면 된다:** 간단한 자기상관 추정에서 A와 C 전체의
  피치 10~90백분위 폭은 각각 약 10.49·10.70반음이었다. 평탄한 단일 음정은 아니다.
  이 방법은 음성 분석기이며 청취 평가가 아니고 옥타브 오류가 있을 수 있다. 핵심은
  변화 폭 자체보다 변화가 의미상 적절한 위치에 있는지다.
- **길게 한 번에 만들면 해결된다:** B가 모든 글을 한 번에 만들었어도 사용자는 C를 선호했다.
  연결부 제거가 전부는 아니다. 길이를 늘리면 일관성뿐 아니라 발화 안정성도 다시 검증해야 한다.
- **공식 자연스러움/장문 성능이 우리 조건에도 그대로 적용된다:** 논문의 장문 평가는
  중국어·영어 및 화자 적응 CustomVoice 조건이며, 현재 한국어 소유자 음성 Base 복제와
  동일한 실험이 아니다. 한국어 평가에도 WER·화자 유사도와 원하는 감정 연기를 구분해야 한다.
  [기술 보고서 평가 조건](https://arxiv.org/html/2601.15621v1#S4.SS2.SSS6)

**다음 개선의 순서**

1. 비교·생산 경로를 분명히 구분한다. C를 평가할 때는 실제 해당 프리셋과 연결 적용 기록을
   확인한다. 기본값 전환은 별도 결정이며 이 분석에서는 변경하지 않았다.
2. 사람 녹음, 코덱 복원, 동일 대본의 TTS를 비교해 음향 질감과 발화 운율을 분리한다.
   이번에는 앞의 두 파일을 만들었다. 동일 대본 TTS까지 포함한 통제 비교는 아직 하지 않았다.
3. C를 기준으로 회상·설명·위로·질문·밝은 대화 등 서로 다른 대본을 청취 평가한다.
   가능하면 같은 화자의 실제 낭독과 비교하고, 정확성·화자 유사성·자연스러움을 따로 기록한다.
4. 같은 화자의 목표 말투에 맞는 실제 참조를 비교한다. 원본 B는 보존한다.
   참조·분할·샘플링을 동시에 바꾸지 않고 원인을 하나씩 분리한다.
5. 장문에는 의미에 맞는 발화 단위와 문맥 초기화 시점을 시험한다. 쉼은 실제 어미·호흡을
   보존하는지 먼저 확인하고, 페이드·음량 보정·랜덤 피치·랜덤 숨을 일괄 적용하지 않는다.
6. 위 조건에서도 합성 느낌이 남으면 같은 대본·화자의 다른 모델 또는 화자별 추가 학습을
   비교한다. 공식 저장소는 단일 화자 fine-tuning을 지원하지만 자료의 스타일·정확도와
   검증이 필요하고, 16GB GPU에서의 학습 가능 범위나 품질 개선을 미리 보장하지 않는다.
   [공식 fine-tuning 안내](https://github.com/QwenLM/Qwen3-TTS/blob/main/finetuning/README.md)

생산 코드·참조·모델·Seed·큐는 변경하지 않았다. 코드 변경이 없어 회귀 테스트를 재실행하지
