# 사람처럼 들리는 음성을 위한 품질 점검

2026-09-26 갱신. 원본 레퍼런스 B, Qwen 1.7B 표현형, 외부 Seed 13,
long-form HQ를 기준으로 한다. 자연스러움은 ASR 정답률과 다른 평가 항목이다.

**현재 적용 상태:** 입력 방식 A/B 비교에서 사용자가 story·explanation·conversation 모두 A를 선호했다.
A는 `non_streaming_mode=True`로 전체 대본을 먼저 전달하는 조건이다. 기본 표현형·HQ의
실제 생성 구간이 1개일 때 웹과 외부 API에 이 방식을 적용한다. 여러 구간인 요청,
standard 모드, 비교 엔진과 명시적으로 지정한 입력 방식은 기존 설정을 사용한다.
평가는 시험한 세 대본에서 확인했으며 모든 말투의 개선을 확인한 것은 아니다. 아래 장문 연결 실험과는
별개다. 상세 적용 기록은 [쇼츠 품질 기록](shorts-quality-20260925.md)을 따른다.

## 확인한 병목과 적용한 수정

| 항목 | 확인한 문제 | 조치 |
| --- | --- | --- |
| 의미에 따른 쉼 | 짧은 마지막 구간을 합칠 때 질문 뒤의 답변이나 전환 문장을 다시 붙임 | 의도한 질문·감탄·전환 경계를 유지 |
| 전환어 분류 | `자연스럽게`, `자신의`도 `자`로 인식; `하지만,`은 놓침 | 단어 경계와 쉼표를 함께 처리 |
| 긴 질문 | 쉼표에서 나누면 첫 조각에 질문 속성이 붙고 마지막 물음표는 평서문으로 처리 | 실제 구간 끝을 기준으로 질문 속성과 쉼 배정 |
| 숫자 발음 | 긴 문장을 `12,345`의 쉼표나 `03:45`의 콜론에서 나눌 수 있음 | 숫자 사이 구두점은 호흡 경계 후보에서 제외 |
| 재생성 후보 | 문자 오류율이 조금 낮으면 끝부분이 누락된 후보가 검사 통과 후보보다 우선될 수 있음 | 파형 유효성, 검사 통과 여부, 점수 순으로 선택 |
| 의도한 반복 | 강조를 위해 쓴 `천천히 천천히`도 반복 결함으로 감점 | 원고에 있는 반복 횟수와 비교 |
| 긴 구간 검사 | Whisper 입력 기본값이 30초 이후를 버림 | 입력 전체를 전달하고 30초 초과 시 타임스탬프 기반 장문 인식 |
| 빈 WAV | PCM 프레임이 없으면 `hard_reject` 자체가 없었음 | 빈 파형은 명시적으로 거부 |
| 참조 캐시 | 같은 파일명으로 음성이 바뀌어도 이전 프롬프트 재사용 가능 | 음성 내용 해시를 캐시 키에 포함, 최대 4개 유지 |

기존 완료 음성을 새 출력으로 오인해 재사용하지 않도록 외부 요청 fingerprint를 5로 올렸고,
9월 26일 단일 생성 입력 방식 채택 시 6으로 갱신하고 입력 정책도 키에 포함했다.
대본의 표현을 자동으로 바꾸거나, 외부 클라이언트에 Seed·엔진 조절을 허용하지 않는다.

## 문맥을 이어 읽는 비교 실험

현재 합성은 모든 구간을 같은 원본 레퍼런스에서 새로 시작한다. 문장 분할과 쉼 계획을
개선해도 앞 문장의 억양·속도·감정은 다음 구간에 직접 전달되지 않는다.

Qwen의 공개 구현에는 전체 입력 문장을 먼저 조건으로 넣는 `non_streaming_mode=True`가
있다. 이 프로젝트는 기존 기본값 `False`를 사용했다. 전체 문장을 먼저 보는 것이
이 대본에서 유리한지는 비교해야 하며, 항상 더 좋다고 가정하지 않는다.

비교 도구는 같은 대본·구간·Seed·sampling 설정으로 네 파일을 만든다.

1. `baseline.wav`: 기존 입력 방식 + 원본 참조.
2. `full_context.wav`: 전체 문장 입력 + 원본 참조.
3. `continuation.wav`: 전체 문장 입력 + 검증된 직전 구간의 음성 코드와 대본.
   화자 임베딩은 계속 원본 참조에서 가져온다.
4. `continuation_streaming.wav`: 기존 입력 방식 + 검증된 직전 구간의 음성 문맥.
   기존 방식에서 문맥 연결만 바꾼 조건이다. 파일명의 streaming은 Qwen의 모의 입력 방식을
   뜻하며, 이 도구가 오디오를 실시간 전송한다는 뜻은 아니다.

연속성 실험은 원고에 이전 문장을 중복 삽입하지 않고, 단어 시각을 추정해 음성을 자르지도
않는다. 3~20초의 완전한 직전 구간만 사용하며, ASR을 사용할 수 없거나 검사 경고가 있으면
원본 참조로 돌아간다. 문단 전환과 전환·결론 문장에서도 초기화하고, 한 번 이어 읽은 뒤에는
다음 구간을 다시 원본 참조에서 시작해 누적 변형을 제한한다. 동일한 화자 임베딩을 유지해도
합성된 음성 코드에서 음색이 변할 수 있으므로 청취 평가는 여전히 필요하다.

직전 음성을 사용하는 문맥 연결은 Studio/MCP/API 기본 경로에 활성화되어 있지 않다. 아래 로컬 비교 도구로 비교하거나,
후술한 Studio의 문맥 연결 비교 프리셋을 직접 선택한다. 로컬 비교 도구는 서비스 큐가 비어
있고 Qwen 워커가 꺼진 상태에서 실행한다.

```powershell
.\.runtime\engines\qwen3-tts\venv\Scripts\python.exe tools\compare_prosody.py
```

자신의 대본과 생산 기본 구간 길이로 비교하려면:

```powershell
.\.runtime\engines\qwen3-tts\venv\Scripts\python.exe tools\compare_prosody.py --text-file data\comparison-script.txt --max-chars 180
```

기본 예문은 경계를 관찰하기 위해 140자를 목표로 나눈다. 실제 서비스의 180자 기본값은
바뀌지 않는다. 결과는 새로운 `data/comparisons/prosody-*` 폴더에 저장한다.
`report.json`은 대본, 참조 해시, 샘플링 설정, 파일 해시, 인식 결과, 경계 피치·음량 차이를
기록한다. 기존 폴더를 덮어쓰지 않고, 서비스 DB를 수정하거나 외부에 데이터를 보내지 않는다.
모델은 로컬 캐시에서 읽는다.

## 다음 개선의 우선순위

1. **연속성의 청취 검증.** 슬픔·회상·설명·질문·흥분 등 서로 다른 대본에서 비교한다.
   경계의 피치 변화가 작다는 이유만으로 좋은 결과라고 판단하지 않는다. 의도한 강조와
   질문의 상승 억양은 유지되어야 한다. 발화 누락·중복, 원본 화자의 음색, 경계의 속도 변화,
   문단 전체의 감정 흐름을 각각 확인한다. 기본값 전환 전에는 10분 이상 대본도 평가한다.
2. **한국어 읽기 사전과 미리보기.** `3시`(세 시), `3분`(삼 분), `17.5%`(십칠 점 오 퍼센트),
   약어·제품명처럼 문맥에 따라 읽기가 달라지는 부분을 명시할 수 있어야 한다. 현재는
   원하는 발음을 대본에 풀어 쓰는 방법이 가장 확실하다. 모든 숫자와 영문을 일괄 치환하면
   오히려 의미를 바꿀 수 있으므로 자동 변환은 아직 도입하지 않았다.
3. **감정별 실제 참조.** 동일 화자의 차분함·회상·밝은 설명 등 실제 녹음으로 별도 비교를
   준비할 수 있다. 현재 선택된 참조는 유지한다. 음색이 닮는 것과 감정 연기가 자연스러운 것은
   다르며, 한 개의 참조만으로 모든 표현을 해결한다고 보지 않는다.
4. **낮은 음량의 자음·숨 검사.** 현재 절대 진폭 기반 가장자리 트리밍과 40ms 패딩이 작은
   숨·말끝을 보존하는지 실제 파일로 점검할 필요가 있다. 이번 작업에서 트리밍·페이드·음량
   정규화 알고리즘은 바꾸지 않았다. 일괄 음량 보정은 의도한 감정 변화를 지울 수 있다.

## 대본 작성 시 바로 도움이 되는 점

- 한 문단에 하나의 생각과 감정 흐름을 담는다. 의미가 바뀌는 곳에 빈 줄을 둔다.
- 읽을 말만 적고, `[슬프게]`, `(웃으며)` 같은 지문을 대사에 섞지 않는다.
- 숫자·약어는 청자가 들을 발음으로 적는다. ASR도 숫자 표기와 실제 읽기의 차이를 오류로
  볼 수 있으므로 이런 구간의 점수는 음성과 함께 확인한다.
- 쉼표를 모든 어절에 넣기보다 실제 사람이 숨 쉬거나 뜻을 나누는 위치에 사용한다.

현재 사용하는 Base voice-clone 모델은 CustomVoice/VoiceDesign의 자연어 감정 지시 모델과
다르다. 문장 앞에 감정 지시를 붙이는 기능을 지원한다고 가정하면 그 지시가 발화될 수 있다.
공개 모델 기능과 입력 경로는 [Qwen 공식 저장소](https://github.com/QwenLM/Qwen3-TTS)와
[공식 추론 코드](https://huggingface.co/spaces/Qwen/Qwen3-TTS/blob/main/qwen_tts/inference/qwen3_tts_model.py)를
기준으로 확인했다. 코드 실행 시에는 이 PC에 설치된 qwen-tts 0.1.1 구현을 사용했다.

## 로컬 확인 결과

- 최근 요청의 구간 126개는 모두 30초 이하였고, 가장 긴 구간은 24.48초였다.
  따라서 30초 잘림이 최근 모든 출력 문제의 원인이었다고 보지는 않는다.
- 기존 요청 #75의 35.29초 전체 음성을 별도로 검사했다. 기존 Whisper 입력은 마지막
  두 문장을 놓쳐 문자 오류율이 26.46%였고, 수정한 입력은 끝까지 인식해 5.82%였다.
  남은 인식 오타가 있으며, 이것은 합성 음질의 향상 수치가 아니라 **검사기의 개선**이다.
- 기존 장문 요청 #72·#73에 새 분할기를 적용해도 구간 수는 각각 42·45개로 유지됐다.

216자 예문을 138자·77자 두 구간으로 나누고 원본 참조와 Seed 13으로 비교했다.
구간 앞뒤 1.5초의 유성 프레임에서 추정한 피치와 활성 프레임 RMS의 차이이며,
작을수록 항상 자연스럽다는 뜻은 아니다. 첫 구간은 연결 실험과 대응 기준 조건이 동일하다.

음량 변화는 커졌다. 전체 문장 입력은 기준 조건보다 생성·검사 시간이 약 2.3배였다.
**한 짧은 예문의 결과로 실험 기능을 생산 기본값에 채택하지 않았다.**
다양한 대본의 청취 평가와 장문에서의 화자·속도 유지 검증이 다음 단계다.

실제 음성과 JSON 기록: `data/comparisons/prosody-20260924-v2/`.
같은 폴더의 `listen.html`은 조건 이름을 가리고 비교한 뒤 펼쳐 확인할 수 있다.

## 연속성 개선 2차: 실제 합성 결과

첫 실험에서 기존 입력 방식의 문맥 연결은 두 번째 구간을 9.60초에서 8.16초로 짧게 만들었다.
따라서 경계 피치뿐 아니라 동일 대본의 길이·말속도 변화도 함께 기록하도록 비교 도구를 추가했다.
경계 RMS는 말끝과 다음 문장의 첫 음절 차이도 반영하므로, 그 수치만으로 음량 보정을 적용하지 않는다.

- **원본 음성 정보를 함께 유지하는 연결**: 원본 녹음의 음성 코드와 직전 구간의 음성 코드를
  순서대로 참조에 넣고, 그 순서와 정확히 일치하는 참조 대본을 사용한다. 화자 임베딩도
  원본 것을 유지한다. 기존 참조 캐시를 수정하지 않으며, 낭독할 대본에는 이전 문장을 넣지 않는다.
- **생성 경계를 줄이는 묶기**: 기준 음성에서 실제로 측정한 길이를 이용해 같은 흐름의 구간을
  예상 28초·280자 안에서 합친다. 문단, 질문·감탄 뒤, 전환·결론 앞에서는 합치지 않는다.
  28초는 예상치이며, 생성된 음성의 길이를 보장하는 제한은 아니다. 생성 후 실제 길이와
  인식 결과를 다시 검사한다. 생성 길이 확대는 비교 도구에서만 실행한다.

원본 참조 해시, Seed, 모델, sampling 설정, 분할 대본과 WAV 해시가 일치하고 ASR을 통과한
기준 음성만 재사용한다. GPU 여유 메모리가 6GiB 미만이면 모델을 올리기 전에 멈추며,
다른 프로젝트의 프로세스를 자동 종료하지 않는다.

GPU 없이 계획을 검사하려면:

```powershell
.\.venv\Scripts\python.exe tools\compare_continuity.py --baseline-report data\comparisons\prosody-20260924-v2\report.json --analyze-only
```

GPU가 확보된 뒤 실제 비교 음성을 생성하려면:

```powershell
.\.runtime\engines\qwen3-tts\venv\Scripts\python.exe tools\compare_continuity.py --baseline-report data\comparisons\prosody-20260924-v2\report.json
```

결과에는 `baseline.wav`, `anchored.wav`, `longer_turns.wav`, `report.json`과 이름을 가리고
비교하는 `listen.html`이 포함된다. 실제 결과는 `data/comparisons/continuity-20260924-verified/`에 있다.
