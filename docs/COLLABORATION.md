# 두 PC의 AI 에이전트 협업 규칙

2026-10-23 사용자 최종 합의. VoiceBench와 insta_auto에 동일하게 적용한다.

## 규칙 원본

- 협업 정책은 이 문서에서 관리한다. AGENTS.md에는 문서 위치·재확인 시점·우선순위만 둔다. 두 저장소의 공통 정책은 같은 내용으로 유지한다.
- 작업 시작, 세션 재개·컨텍스트 압축 후, 수정 범위 확장, 병합/push 직전에 실제 원문을 다시 읽는다. 기억이나 대화 요약으로 대신하지 않는다.
- 재개 메모에는 작업 브랜치·기준 커밋·문서 버전(commit 또는 SHA)·진행 단계·미해결 사항·필요한 내용 소실 동의를 남긴다. 비밀정보는 넣지 않는다. 문서를 읽을 수 없으면 변경·병합·push 전에 원문을 확보한다.
- 파일 분리만으로 누락이나 오판이 완전히 차단되지는 않으므로 실제 검사와 원격 반영 확인을 유지한다.

## 병행 개발

- 두 사람이 서로 다른 PC의 AI 에이전트를 사용하며 모두 저장소 전체를 수정할 수 있다. 같은 저장소·파일의 독립적인 작업도 병행한다. 고정 담당자나 파일 선점은 두지 않는다.
- **GitHub 이슈를 만들지 않으며, 이슈 생성·갱신·종료를 협업 절차로 사용하지 않는다. PR 생성과 별도 PR 리뷰도 필수 절차가 아니다.** 기존 이슈 이력은 삭제하지 않는다.
- 최신 origin/main을 기준으로 작업별 브랜치와 독립 작업 폴더에서 개발한다. 원래 작업 폴더의 미커밋 변경을 초기화·이동·혼입하지 않는다.
- 수정 파일은 작업 중 늘어날 수 있다. 관련 작업 브랜치와 변경을 확인하고 같은 함수의 동작·API·DB·설정 계약이 겹치면 양쪽 의도를 보존해 통합한다.
- 브랜치 이름과 커밋 메시지에 목적을 분명히 남기고 논리적인 작업 단위로 작업 브랜치를 공유한다. 다른 PC의 미커밋 변경은 보이지 않는다는 점을 고려한다. 미완성 변경을 main에 반영하지 않는다.

## 의견을 구하는 경우

- **main 통합 과정에서 사용자 또는 상대 작업자가 만든 기존 코드·기능·문서의 실질적인 내용이 없어지거나 축소될 때만 협업 관련 의견을 구한다.** 적용 전에 없어질 대상·이유·영향·대안을 구체적으로 설명하고 명시적 동의를 받는다.
- 구현의 교체·줄 이동·동작을 유지하는 정리와 실제 내용 소실을 구분한다. 삭제 줄이 있다는 이유만으로 확인을 요구하지 않는다. 이미 같은 대상·범위로 승인받았다면 근거를 남기고 다시 묻지 않는다.
- 상대 코드를 통째로 버리거나 ours/theirs를 일괄 선택해 충돌을 처리하지 않는다. 내용을 보존하는 통합은 AI가 처리하며, 완료 여부·push 승인·일상적인 충돌 해결을 매번 묻지 않는다.

## 완료와 자동 push

1. AI가 구현·검증 완료를 판단한다. 현재 작업의 변경만 커밋하며 다른 작업, 개인 음성·세션·인증정보·모델·로컬 DB·생성 미디어·복구 백업을 포함하지 않는다.
2. 최종 push 직전에 origin/main을 다시 fetch하고 작업 브랜치에 병합한다. 양쪽 변경의 연결과 실제 내용 소실 여부를 확인하고 관련 검사를 수행한다.
3. 내용 소실에 필요한 동의가 해결되고 검사가 통과하면 별도 지시나 완료 확인 없이 일반 fast-forward push로 작업 브랜치의 HEAD를 원격 main에 반영한다. 강제 push·강제 덮어쓰기·검사 실패 무시는 금지한다.
4. 상대의 선행 push로 거절되면 최신 main을 다시 통합하고 영향받는 검사를 다시 수행한다. 진전 없이 같은 실패를 무한 반복하지 않는다.
5. 원격 main이 내 완료 커밋을 포함하는지 확인하고 변경 요약·검사·반영 커밋·남은 제한을 사용자에게 보고한다. 이슈는 만들거나 관리하지 않는다.

## 기존 작업과 운영 보호

코드 반영과 운영 적용은 구분한다. 자동 push는 배포·서비스 재시작·제작·수집·예약·모델·휴대폰 제어·실제 게시 재개를 허용하지 않는다. 기존 사용자 중지, 개인 자료 보존, 서비스 간 API 경계, 프로젝트별 품질 규칙을 유지한다. 실제 운영 확인이 작업의 완료 조건이면 그 확인 전에는 전체 완료로 보고하지 않는다.

이 최신 합의는 앞선 이슈 필수 관리, 매번 사용자 완료 확인, 일반적인 커밋/push 지시 대기 규칙을 대체한다. 과거 작업 이력은 당시 기록으로 보존한다.
